# Onboarding call — Jordi's checklist

*v1 draft. Refine after every run — this document should get better each
install. The interview itself lives in the template: setup/ONBOARDING.md.*

## Before the call

- [ ] Clone `template/` into a new private repo named for the client; client
      is the owner, Jordi a collaborator.
- [ ] Confirm which surface this client will use (Claude Desktop or VS Code)
      and have it working on the call machine.
- [ ] Skim anything already known about the business (site, prior calls) —
      arrive warm, not cold.
- [ ] Send agenda.md the day before.

## During the call (~90 min)

- [ ] Set the frame in one line: "This call produces decisions and a build
      list, not ideas — by the end, your system works and your first
      automation has a date."
- [ ] Run the interview (setup/ONBOARDING.md) conversationally — owner's
      words, no polishing.
- [ ] Part 6 gets the most time: walk each painful workflow start to finish;
      capture where they pause to check things (those become human
      checkpoints).
- [ ] Score workflows together: time/money saved × ease of automating.
- [ ] Pick 1–3. Schedule the first build with a real date into Up next.
- [ ] Run the generation rules; show the owner their filled system live —
      ask it one real question about their business before ending.

## After the call

- [ ] Verify: knowledge/ files filled, STATE.md real, no [BRACKETS] left,
      setup/ deleted, first commit pushed.
- [ ] Note credentials still needed for build #1 and request them (client
      creates, client owns — see the connections rules).
- [ ] Send a short recap in plain English: what their OS knows, what's being
      built, the date.
- [ ] Add anything learned to this checklist.
