# playbook/ — Rhiza's side of the product

Jordi's operating materials for delivering the OS. **Nothing in this folder is
ever copied into a client's install.**

The pattern (adapted from Paul Kim's engagement repo): every recurring client
interaction gets a pair —

- **agenda.md** — client-facing: what we'll cover, what you'll leave with.
  Can be sent to the client before the meeting.
- **playbook.md** — internal: the checklist Jordi actually runs, refined
  every time it's used.

Contents:

- `onboarding-call/` — the install meeting (agenda + playbook)
- `monthly-tuneup/` — the retainer's monthly pass (agenda + playbook)
- `workspace-shapes.md` — reference Claude reads when proposing a workspace
  shape for a client workflow; not something anyone memorizes

The canonical job description (everything the retainer covers) lives in the
Rhiza OS: `knowledge/retainer-job-description.md`.
