# workspaces/ — where repeating work gets done

A workspace is a folder for one piece of real work: a launch, a partner
campaign, a course build, a weekly client report. Everything that belongs to
that job lives in its folder, so nothing is scattered across chats, a
spreadsheet and a Drive folder when the week gets loud.

Two shapes, and picking the right one matters:

- **A launch** — anything with a date: a launch, a one-off workshop, a
  promo, a swap. It gets a folder in `launches/`, named plainly for the
  offer and the month (`pivot-lab-november-2026`), with one
  `launch-facts.md` holding its dates, prices, links and people. What the
  launch produces sits beside it: `calendar.md`, `messaging.md`,
  `partner-kit.md`, `registrations.md`, `follow-up.md`. When it's done it
  stays, because the next one starts by reading the last one.
- **A repeating job** — same steps each time, a new result each time, with a
  checkpoint where a person looks before things move on. A weekly report, a
  monthly newsletter, onboarding a new client. It gets numbered step folders
  and a CONTEXT.md contract per step: what it reads, what it does, what it
  writes, and what a human checks.

`pipeline/` holds the people who might buy, when they don't live in a tool
you already use; its README says more.

Apart from that, there's nothing here yet on purpose. Workspaces get created deliberately —
during onboarding, or whenever a genuinely repeating piece of work shows up.
Work that's only happened twice doesn't get a workspace yet — unless the
owner and the OS scope one together off a real run. Chosen is different
from assumed.

A launch starts by talking about it: the launch-facts skill copies
`_template/launch-facts.md` and fills it in. Copy `_template/CONTEXT.md` to
start a step of a repeating job.

One launch per folder, so "what did we do last time" is one file away. What
a program teaches lives in `knowledge/programs/`, not here.
